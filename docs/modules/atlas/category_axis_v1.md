## Atlas Category Axis v1 (категория как сквозная смысловая ось)

**Статус**: design note / v1  
**Ограничения v1**:
- Без изменений схемы БД (Neon).
- Без введения backend `/search`.
- Категория — **derived metadata** (вычисляется из `tags`).

См. также:
- `docs/decisions/search_strategy.md`
- `docs/standards/search_conventions_v1.md`

---

## 1) Принцип

**Категория = смысловая ось Atlas, а не тип контента.**

- Категория в v1 **не хранится в БД**.
- Категория вычисляется детерминированно из `tags` по общей taxonomy v1.
- В v1 категория работает как:
  - “быстрый смысловой фильтр”,
  - “линкер” между разными формами контента.

Источник истины taxonomy:
- `packages/atlas-taxonomy` (v1)

---

## 2) Модель “один смысл — разные формы”

Одна и та же категория связывает разные формы контента в Atlas:

- **Places (места)**: списки/карточки мест (достопримечательности, заведения).
- **Guides (гайды)**: редакционные/UGC-гайды, привязанные к темам/городам/местам.
- **Themes / Collections (темы/подборки)**: curated-наборы карточек или страниц навигации по смыслу.
- **Country tabs / City tabs (вкладки страниц страны/города)**: curated-вьюхи в конкретном scope (страна/город), которые “ведут по смыслу”.

Идея: пользователь может “переезжать” по смыслу между:
**Places ↔ Guides ↔ Themes ↔ (Country/City вкладки)**,
не теряя выбранную категорию.

---

## 3) Использование категории в разделах (v1)

### 3.1 Places

- Категория = alias набора тегов:
  - категория вычисляется из `tags`,
  - фильтр категории применяет теговый набор категории.
- Facets (categories/tags):
  - в v1 могут вычисляться client-side,
  - позже — сервером/движком, но shape остаётся совместимым.

### 3.2 Guides

- У гайдов должны быть `tags` (как метаданные контента).
- Категория вычисляется **тем же алгоритмом**, что и для Places.
- На списках гайдов допустим фильтр по `categoryKey` (v1 — client-side, позже — server-side).

### 3.3 Themes / Collections

- Тема/подборка описывается через `tags` (или фиксированный `categoryKey` в метаданных, но без БД).
- В v1 категория:
  - вычисляется из `tags` или фиксируется в метаданных темы,
  - используется для фильтрации/навигации по списку тем.

### 3.4 Country/City вкладки

Вкладка трактуется как **curated view** категории в конкретном scope:
- `country` scope: `countryId=...`
- `city` scope: `cityId=...`

В v1 вкладки могут вести на листинг с предустановленными параметрами:
- `categoryKey=<...>`
- `countryId=<...>` или `cityId=<...>`

Важно: это **не “поиск”**, а **смысловая навигация**.

---

## 4) Навигационный паттерн (единый)

Целевой паттерн переходов в UI (v1 может быть просто переходом на листинг с параметрами):

- “Показать всё по категории **X** в городе **Y**”
  - `.../places?cityId=Y&categoryKey=X`
  - `.../guides?cityId=Y&categoryKey=X`
  - `.../themes?cityId=Y&categoryKey=X` (если применимо)

- “Показать гайды по категории **X**”
  - `.../guides?categoryKey=X`

- “Показать места по категории **X**”
  - `.../places?categoryKey=X`

---

## 5) Связь со стандартом параметров поиска (v1)

См. `docs/standards/search_conventions_v1.md`.

Ключевые правила:
- Текстовый поиск: **`q`**
- Категория: **`categoryKey`** (ключ taxonomy, derived metadata)
- Теги: **`tags=tag1,tag2`** (CSV)
- Scope: `countryId`, `cityId`
- Пагинация: `limit` + `cursor` (целевой стандарт)
