## Counts Conventions v1 (total vs filtered counts)

**Статус**: standard v1  
**Область**: все модули (Atlas, Pulse, Blog/Media, Guru, Rielt, RF, Space, User, …)  
**Цель**: единый UX-стандарт отображения счётчиков (total vs filtered) для предсказуемого и сильного UX.

См. также:
- `docs/decisions/search_strategy.md`
- `docs/standards/search_conventions_v1.md`

---

## Принцип (важно)

**Total counts** показываем там, где пользователь **"осматривается"** (контекст/масштаб).  
**Filtered counts** показываем там, где пользователь **"выбирает"** (эффект клика).

**Не смешиваем** эти два смысла в одном UI-элементе.

---

## A) В фильтрах (Select/Dropdown/Chips) — ТОЛЬКО filtered counts

### Правило

В фильтрах показываем **filtered counts** — количество результатов, которое будет при выборе этого фильтра **с учётом текущих активных фильтров** (self-exclusion).

### Примеры

- **Страны в select**: `"Вьетнам (5)"` — означает "столько результатов будет при выборе Вьетнама сейчас" (с учётом других активных фильтров, кроме countryId).
- **Города в select**: `"Бали (12)"` — означает "столько результатов будет при выборе Бали сейчас" (с учётом других активных фильтров, кроме cityId).
- **Категории**: `"Ночная жизнь (3)"` — означает "столько результатов будет при выборе этой категории сейчас" (с учётом других активных фильтров, кроме categoryKey).

### Self-exclusion логика

При подсчёте facets для фильтра **исключаем сам фильтр** из активных:

- **countryFacets**: считаются по выборке **БЕЗ** фильтра `countryId`, но с остальными фильтрами (kind, onlyWithPhotos, и т.д.).
- **cityFacets**: считаются по выборке **БЕЗ** фильтра `cityId`, но с учётом выбранной страны (если выбрана) и остальными фильтрами.
- **categoryFacets**: считаются по выборке **БЕЗ** фильтра `categoryKey`, но с остальными фильтрами.
- **tagFacets**: считаются по выборке **БЕЗ** фильтра `tags`, но с остальными фильтрами.

### ❌ НЕ показывать в фильтрах

- Total counts (общее количество без фильтров) — это ломает ожидания пользователя.
- Counts без учёта других активных фильтров — это даёт неверные цифры.

## B) Total counts — ВНЕ фильтров, в контекстных местах

### B1) В заголовке списка (над grid карточек)

**Формат**: `"Название — N"`

Примеры:
- `"Места — 312"`
- `"Места во Вьетнаме — 58"`
- `"Гайды по Таиланду — 14"`
- `"Темы по Вьетнаму — 9"`

**Где**: над grid карточек, рядом с заголовком раздела.

**Что считать**: total count для текущего scope:
- Если выбрана страна → total places в этой стране.
- Если выбран город → total places в этом городе.
- Если scope не выбран → total places overall.

**Источник данных**:
- Предпочтительно: поле `placesCount` из данных страны/города (если доступно в API).
- Fallback: количество загруженных мест (если все загружены) или приблизительная оценка.

### B2) На страницах страны/города — компактный блок статистики

**Где**: под hero или рядом с названием страны/города.

**Формат**: `"312 мест • 14 гайдов • 9 тем"`

**Использование**: для быстрого понимания масштаба контента в этом scope.

### B3) В карточках стран/городов в их листингах

**Формат**: `"Страна (312 мест)"` или `"Город (58 мест)"`

**Где**: в списках стран/городов (например, Atlas → Countries, Atlas → Cities).

---

## C) "Показано N" (filtered results) — рядом с grid

**Формат**: `"Показано: K"`

**Где**: справа от заголовка или под grid карточек.

**Что считать**: количество результатов, **отображаемых сейчас** после применения всех активных фильтров (включая клиентские: категории, теги, сортировка).

**Это НЕ total count**, а текущий срез результатов.

## Реализация filtered counts (технические детали)

### Проблема

Counts могут быть неверными, если facets считаются по подвыборке, ограниченной:
- `limit` в API,
- уже применёнными фильтрами,
- неправильным порядком применения фильтров.

### Решение (v1)

1. **Self-exclusion**: при подсчёте facets для фильтра исключаем сам фильтр из активных.
2. **Порядок фильтров**: facets считаются после применения базовых фильтров (kind, onlyWithPhotos), но **до** применения фильтра, для которого считается facet.
3. **Если из-за limit невозможно считать честно на клиенте**:
   - Временное решение: увеличить `limit` для подсчёта facets (pragmatic fix).
   - Лучший путь: считать facets на backend (без изменения БД; можно отдельный endpoint позже).
   - Минимальный безопасный вариант: явно маркировать counts как "по загруженной выборке" — но это нежелательно.

### Пример реализации (Atlas Places)

```typescript
// Базовая выборка для facets: после фильтров kind и "С фото", но БЕЗ фильтров по стране/городу/категории/тегам
const placesForFacets = useMemo(() => {
  return placesWithPhotoFilter; // уже отфильтрованы по kind и onlyWithPhotos
}, [placesWithPhotoFilter]);

// countryFacets: считаем БЕЗ фильтра countryId
const countryFacets = useMemo(() => {
  const counts = new Map<string, number>();
  for (const place of placesForFacets) {
    if (place.countryId) {
      counts.set(place.countryId, (counts.get(place.countryId) ?? 0) + 1);
    }
  }
  return countries.map((country) => ({
    ...country,
    count: counts.get(country.id) ?? 0,
  }));
}, [placesForFacets, countries]);
```

## Применение к модулям

Этот стандарт применяется ко **всем модулям** Go2Asia:

- **Atlas**: Places, Guides, Themes, Countries, Cities
- **Pulse**: Events (фильтры по стране/городу/категории)
- **Blog/Media**: Articles (фильтры по рубрикам/тегам)
- **Rielt**: Listings (фильтры по городу/типу/удобствам)
- **Guru**: Objects (фильтры по типу/радиусу/атрибутам)
- **RF**: Partners, Vouchers (фильтры по категориям/атрибутам)

## Чек-лист для внедрения

При добавлении фильтров с counts в новый модуль:

- [ ] Filtered counts в dropdown/chips используют self-exclusion логику.
- [ ] Total count отображается в заголовке/контексте (не в фильтрах).
- [ ] "Показано: K" отображается как filtered count текущих результатов.
- [ ] Counts не превращаются в "везде нули" при выборе значения фильтра.
- [ ] Источник данных для total count определён (API field или fallback).
