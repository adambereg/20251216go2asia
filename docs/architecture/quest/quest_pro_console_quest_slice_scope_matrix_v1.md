# Quest PRO Console — Quest Slice Scope Matrix v1

**Project:** Go2Asia  
**Module:** Quest Asia  
**Document role:** Hard scope guardrails for Quest PRO Console UI definition and first implementation wave  
**Status:** Planning-only; no implementation included

---

## In scope

- Quest-first PRO Console IA for first UI wave
- `My quests` management list
- Quest management detail view
- Draft edit UI-definition for bounded quest fields
- Step management UI-definition for bounded operations
- Publish/archive controls UI-definition with lifecycle/readiness feedback
- Per-quest review queue UI-definition
- Curator stats minimum usage in Quest management context
- Reference selection surfaces (Atlas/Pulse/RF) at UI-definition level only
- First-wave Quest operations map aligned to existing backend seams

---

## Out of scope

- Any code implementation (backend/frontend/OpenAPI/SDK/schema/importer)
- Real screen/component development
- Full visual builder architecture
- PRO Console design for non-Quest modules (Pulse/RF/Space/Blog/etc.)
- Business console or admin console architecture
- Player-facing Quest UI changes
- Design-system overhaul or platform-wide UI refactor
- Analytics/growth/reporting platform definition
- Moderation platform definition

---

## Explicitly deferred

- Rich visual builder (advanced authoring UX)
- Drag-and-drop workflow editor
- Collaborative editing / multi-editor locking
- Advanced analytics (trends, cohorts, funnels)
- Broad cross-module PRO workspace shell
- Unified cross-domain dashboard architecture
- Deep reference picker UX beyond bounded Quest forms
- Extended audit/history UI surfaces

---

## Enforcement intent

This matrix is a strict guardrail for upcoming implementation prompts.

If a proposed UI task requires crossing into out-of-scope or deferred areas, it must be split into a later planning/implementation phase rather than expanded in Quest-first wave.
