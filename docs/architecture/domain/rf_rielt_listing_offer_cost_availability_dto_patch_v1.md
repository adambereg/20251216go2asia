## Purpose

This patch closes the first practical Stage 7.8b drift: listing offer read context must not lose RF offer `pointsCost`, and `availability` must not be mistaken for voucher lifecycle, claimability, redeemability or spendability.

This is a stabilization patch only. It does not add claimability DTOs, redeemability DTOs, CTA states or new lifecycle semantics.

## Non-goals

This patch does not:

- change RF claim semantics;
- change RF redeem semantics;
- change Points semantics;
- introduce claimability or redeemability DTOs;
- add CTA projection adapter;
- add CTA state enums;
- rename `availability`;
- introduce new RF lifecycle states;

- create a cost service;
- create an economy abstraction;
- regenerate SDK;
- redesign frontend;
- add migrations;
- run staging;
- activate runtime rollout.

## Drift Addressed

| Drift | Stage 7.8b severity | Patch response |
|---|---|---|
| Listing offer `pointsCost` can read as `0` while listing claim uses actual offer cost. | `dangerous` / `implementation-blocking` | Include `o.points_cost` in listing offer context query so `toOffer(row)` receives the same offer cost field. |
| `RfRieltListingOffer.availability: available` can be read as voucher `canonicalStatus`, claimability, redeemability or spendability. | `dangerous` / `implementation-blocking` | Clarify OpenAPI and SDK wording without changing schema shape. |
| `pointsCost` can be read as money, listing price, payment or booking fee. | `dangerous` economy-risk drift | Clarify OpenAPI and SDK wording as internal Points utility cost for RF claim only. |

## Backend Patch Summary

File changed:

- `apps/rf-service/src/store.ts`

Change:

- `getRieltListingOfferContext` now selects `o.points_cost` from `rf_offer`.
- Existing `toOffer(row)` already maps `pointsCost: Number(row.points_cost ?? 0)`.
- Listing offer context therefore preserves the RF offer Points cost instead of defaulting to `0` because of a missing SELECT column.

No claim logic changed:

- `claimVoucherForListing` already reads `o.points_cost AS offer_points_cost` through listing claim context.
- Stage 7.9 only aligns listing offer read context with that existing offer field.
